# 06 — تحويل الأرقام إلى كلمات عربية (التفقيط / Tafqeet)

> **التطبيق:** AbbasiyCashiers — Ecas v18.4 — `com.egy.webpaymentapp`
> **النطاق:** خوارزمية `tafqeet()` المُستخدمة لتحويل المبلغ الرقمي إلى نص عربي على الإيصال
> **منهج التحليل:** محقق محايد — اكتشاف من الكود الفعلي + اختبار ميداني للخوارزمية في Node.js
> **مصادر التحليل:**
> - `AbbasiyCashiers_RE_Analysis/02_apktool_output/AbbasiyCashiers/assets/myweb/js/report.js`
> - `AbbasiyCashiers_RE_Analysis/02_apktool_output/AbbasiyCashiers/assets/myweb/vReport.html`
> - اختبار تنفيذي مباشر في Node.js v20 (24+ حالة)

---

## 1. الملخص التنفيذي

تطبيق AbbasiyCashiers **لا يحتوي على خوارزمية تفقيط في كود Java/Kotlin**. التفقيط يتم بالكامل في **JavaScript** داخل `assets/myweb/js/report.js`، عبر دالة باسم `tafqeet()`، تُستدعى من قالب الإيصال `vReport.html` المُحمَّل في WebView مخفي قبل توليد PDF.

الخوارزمية:
- ✅ **تدعم** الأعداد حتى **مليارات** (مع وجود مستويات أعلى — ترليون/كوادرليون/كوينتليون/سكستليون — معرّفة في القاموس).
- ✅ **تدعم** الكسور (فلس) — كسر من خانتين (2 decimals) معرّف في إعدادات `YER`.
- ✅ **تتعامل** مع الجنس النحوي (مذكر/مؤنث) للأعداد — لكن بشكل ثابت حسب جنس العملة وجنس الكسر.
- 🟡 **متوسطة** في إعراب المئات (مائة/مائتا/ثلاثمائة...) — لكن لا توجد علامات إعراب نهائية (الرفع/النصب/الجر).
- 🔴 **عيوب موثقة** في:
  - السلبية المُتجاهلة (negatives silently dropped).
  - عدم التحقق من المدخل (`tafqeet("123abc")` ينتج خرجاً مشوهاً).
  - عدم تمييز المفرد/المثنى/الجمع لعملة الريال اليمني — كل الصيغ ثابتة على `"ريال يمني"`.
  - أخطاء إملائية في أسماء الأعداد الكبيرة جداً (`كوادرليون` بدل `كوادريليون`).

> الخلاصة المحايدة: الخوارزمية **تعمل بدقة معقولة** للنطاق الفعلي للتطبيق (مبالغ تحصيل عادية)، لكنها **مكتوبة بأسلوب مُموَّه/مُلتبس** (كل النصوص في مصفوفة `_$_174b` بـ Unicode escapes)، وفيها أخطاء حافة لم تُختبر.

## 3. هيكل القاموس (`tafqeetISOList`)

موقع التعريف في الكود:

**`report.js:1` (السطر الأخير من الملف):**
```javascript
let tafqeetISOList = {
  YER: {
    uSingle:  "ريال يمني",   // مفرد الوحدة
    uDouble:  "ريال يمني",   // مثنى الوحدة
    uPlural:  "ريال يمني",   // جمع الوحدة
    uGender:  "male",        // جنس الوحدة
    sSingle:  "فلس",         // مفرد الكسر
    sDouble:  "فلس",         // مثنى الكسر
    sPlural:  "فلس",         // جمع الكسر
    sGender:  "male",        // جنس الكسر (المصدر يُظهر male لكن بمعالجة 'female' في الكود)
    fraction: 2              // عدد خانات الكسر
  }
};
```

> **اكتشاف 🔴:** القاموس **يعرّف YER فقط** — لا توجد عملات أخرى. لو تغيرت العملة في الإصدارات القادمة (مثلاً USD، SAR) سيرمي خطأ:
> ```javascript
> let _0x9A6D = tafqeetISOList[_0x99D9];
> if (!_0x9A6D) { throw new Error("Currency code not in the list!"); }
> ```

> **اكتشاف 🔴 — مشكلة الجمع غير المُعبَّر عنه:** الحقول الثلاثة `uSingle`، `uDouble`، `uPlural` كلها = `"ريال يمني"` — هذا يعني الخوارزمية **عاجزة عن إنتاج صياغة عربية صحيحة** للتعدد:
> - الصحيح: `1 ريال`، `2 ريالان`، `3-10 ريالات`، `11+ ريالاً`.
> - الفعلي في التطبيق: كل المبالغ تنتهي بـ `"ريال يمني"` بغضّ النظر عن العدد.

## 4. الخوارزمية — تشريح كامل

### 4.1 المعمارية

```
tafqeet(amount, currencyCode, options)
   │
   ├── 1. عَلِّم الجزء الصحيح والكسر:
   │      let parts = (amount + "").split("0.1".toString().substring(1,2));
   │      // .substring(1,2) من "0.1" = "." → splitter
   │      // parts[0] = الجزء الصحيح   parts[1] = الجزء الكسري
   │
   ├── 2. _0x9AB7(parts[0], genderIsFemale, options, [uSingle,uDouble,uPlural])
   │      └── يُفقِّط الجزء الصحيح + يُلحق اسم الوحدة (ريال يمني)
   │
   └── 3. إن كان هناك كسر:
          ├── ضع 0 في الخانات الناقصة (.5 → "50")
          ├── ضِف " و"
          └── _0x9AB7(fractionPart, ...) + sUnit (فلس)
```

### 4.2 الدوال الداخلية

#### الدالة `_0x9AB7(num, femaleGender, opts, units)` — معالج الرقم الكامل

تقوم بـ:
1. تجزئة الرقم إلى **مجموعات ثلاثية** بـ `match(/.{3}/g)`، مع **حشو يساري بأصفار** ليصبح طوله مضاعف 3:
   ```javascript
   let _0x9C73 = ~~(((num = "0".repeat(num.length * 2 % 3) + num)
                       .replace(/0+$/g, "").length + 2) / 3) - 1;
   ```
2. تمرير على كل ثلاثية مع تسمية مرتبتها (آلاف، ملايين، مليار...).
3. وصل النتيجة بكلمة الوصل " و".
4. إلحاق اسم الوحدة بصيغة المُفرد/المثنى/الجمع حسب آخر رقمين:

```javascript
let _0x9D07 = +(_0x9DE5 + "").slice(-2);   // آخر رقمين من العدد
if (_0x9D07 > 10) {
    _0x9E79 = " " + _0x9D9B[0];            // > 10  → uSingle  (ريال يمني)
} else {
    if (_0x9D07 > 2) {
        _0x9E79 = " " + _0x9D9B[2];        // 3–10  → uPlural  (ريال يمني)
    } else {
        if (_0x9D07 > 0) {
            _0x9E79 = (femaleGender ? _0xFEMS[_0x9D07] : _0xMASS[_0x9D07])
                     + " " + _0x9D9B[0];   // 1–2   → uSingle مسبوقة بصيغة الجنس
        }
    }
}
```

#### الدالة `_0x9BDF(rank, three_digits, isLast)` — معالج الثلاثية

تقوم بفك الثلاثية إلى مئات + عشرات + آحاد + إلحاق اسم المرتبة (ألف/مليون/مليار...):
- `_0xA113` = خانة المئات (0-9).
- `_0xA0C9` = خانة العشرات (0-9).
- `_0xA15D` = خانة الآحاد (0-9).
- يستخدم القاموس `_0x9FA1` = `[, "ألف", "مليون", "مليار", "ترليون", "كوادرليون", "كوينتليون", "سكستليون"]`.

> **اكتشاف 🟡:** الإملاء المُستخدم:
> - `"كوادرليون"` ← الصحيح إملائياً **"كوادريليون"**.
> - `"كوينتليون"` ← الصحيح **"كوينتيليون"**.
> - `"سكستليون"` ← الصحيح **"سكستيليون"**.
> 
> هذه أخطاء إملائية لن تظهر للمستخدم العادي (لأن المبالغ لا تصل لهذه المستويات)، لكنها تكشف عن قلة التدقيق اللغوي.

## 5. الفاصل ومعالجة الكسر

موقع الكود:

```javascript
let _0x998F = (_0x9B01 += "").split((0.1).toString().substring(1, 2)),  // splitter = "."
    _0x9B95 = _0x9AB7(_0x998F[0], ...),                                  // الجزء الصحيح
    _0x9A23 = _0x998F[1]
              ? (_0x998F[1] + "000").substring(0, _0x9A6D.fraction)      // padding بـ "000"
              : 0;

if (_0x9A23 != 0) {
    _0x9B95 += " و" + ( opts.legal == "short"
                        ? _0x9A23 + "/1" + "0".repeat(+_0x9A6D.fraction) + " " + uSingle
                        : _0x9AB7(_0x9A23, sGender == "female", opts, [sSingle, sDouble, sPlural])
                      );
}
```

**سلوكان مختلفان:**
1. **الوضع الاعتيادي** (افتراضي): تفقيط الكسر إلى كلمات → `"خمسون فلس"`.
2. **الوضع القانوني** (`opts.legal === "short"`): يُظهر الكسر كرقم على شكل كسر اعتيادي → `"50/100 ريال يمني"`. **هذا الوضع غير مُستخدم في التطبيق** (لا أحد يمرر `legal:"short"`).

> **اكتشاف 🔴:** الـ padding يضيف **`"000"` ثم يأخذ أول `fraction` خانة**. هذا يجعل `0.5` يصبح `"500".substring(0,2) = "50"` (أي 50 فلس)، وهو المنطقي. لكن `0.05` يصبح `"05".substring(0,2) = "05"` ← يُفسَّر كـ `5` فلس. **لا توجد مشكلة في القراءة العملية**، لكن `0.005` يصبح `"005"` ← يُؤخذ منه `"00"` = **0 فلس!** بدون أي تحذير أو خطأ.
> 
> ⚠️ **توابع مالية:** الفلس الواحد قد يضيع إذا أرسل الـ Backend رقماً بـ 3 أو 4 خانات عشرية.

## 6. الجنس النحوي

التطبيق يدعم الجنس النحوي للوحدة والكسر بشكل **مفصول**:
- `uGender` للريال = `"male"` ← يستخدم مصفوفة `_0x9F57` (المذكر).
- `sGender` للفلس = `"male"` في القاموس، لكن الكود يقارن بـ `"female"`:
  ```javascript
  _0x9AB7(_0x9A23, _0x9A6D.sGender == "female", ...)
  ```
  بما أن `sGender = "male"` ← يستخدم مصفوفة المذكر للفلس أيضاً.

**نتيجة عملية:** الفلس يُفقَّط بصيغة المذكر:
- `0.5` → `"...وخمسون فلس"` ✅
- `0.2` → `"...واثنين فلس"` 🔴 (الصحيح "**اثنان** فلس" — لكن `sGender=male` في القاموس)

> **اكتشاف 🟡:** الصياغة العربية الفصحى تستوجب أن يكون الفلس مؤنث (الفلس = اسم ولكن في السياق المحاسبي القديم تتعدد القراءات). الخوارزمية تنفذ ما يخبرها به القاموس، وفي القاموس `sGender:"male"` ← لذا تُنتج صيغ مذكرة. لو رغب المطور بتأنيث الفلس يكفي تغيير `sGender` إلى `"female"`.

> سبب الخطأ في الكود: مصفوفة `_0x9F57[2]` تساوي `_$_174b[109]` = **"اثنين"** (صيغة النصب/الجر)، وكان الأَولى استخدام "اثنان" (صيغة الرفع) في سياق العدد المبتدأ.

> **اكتشاف 🟡:** هناك سياقات نحوية متعددة (رفع/نصب/جر) لكن الكود يستخدم صيغة واحدة دائماً. مثال: `"تسعة وتسعون"` (نصب/جر) بدلاً من `"تسعة وتسعون"` (رفع — لا فرق في هذه الحالة بسبب صيغة "ون") — هنا الخوارزمية تنجو، لكن `"اثنين"` تكشفها.

## 9. اكتشافات صادمة (Unexpected Findings)

### 9.1 التمويه المتعمَّد للنص العربي

**كل** النصوص العربية مُخزَّنة بصيغة `\u06XX` escapes في مصفوفة عالمية `_$_174b` بحجم 151 عنصراً. السبب الظاهري: **`snapbuilder.com` JavaScript Obfuscator** — أداة تجارية للتشويش.

**أمثلة من ملف `report.js`:**
```javascript
var _$_174b = [
  "...",
  "\u0635\u0641\u0631\x20",          // "صفر "
  "\u0623\u0644\u0641",                // "ألف"
  "\u0645\u0644\u064A\u0648\u0646",    // "مليون"
  // ... 148 entry آخرين
];
```

**لماذا؟**
- ✅ مبرر تقني: تجنّب مشاكل ترميز UTF-8 عبر مختلف WebViews.
- 🟡 يصعّب فهم الكود وصيانته.
- 🔴 يخفي إمكانية مراجعة الإملاء العربي.

### 9.2 لا يوجد تفقيط في كود Java

`grep -ri "tafqeet\|toWords\|inWords\|spell" jadx_output/com/egy/webpaymentapp/` → **0 hits**.

الـ Java لا تعرف شيئاً عن التفقيط — كل شيء يعتمد على WebView + JavaScript.

> **اكتشاف 🔴:** إذا فشل تحميل JavaScript (مثلاً تعطل WebView أو منعت سياسة CSP)، **لن يحتوي الإيصال على تفقيط** — وسيظهر فقط `5000  ` (مبلغ بدون كلمات).

### 9.3 شهادة التمويه

الكود الأصلي مأخوذ من **مكتبة معروفة:** خوارزمية مماثلة منشورة باسم **"tafqeet.js"** على GitHub بأسماء متعددة (محمد شعبان / مجاهد محمد). تم اقتباسها وتشويشها فقط بدون تعديل جوهري.

## 11. التقييم المُحايد

### نقاط جيدة ✅
1. تغطية كاملة من 0 إلى السكستليون (1e21+).
2. معالجة الكسر بشكل صحيح في الحالات الاعتيادية (.01 إلى .99).
3. تطبيق صحيح لإعراب "مائتا/مائتي" بعد الإضافة.
4. أداء ممتاز (دالة في JS بسيطة).
5. هيكل قابل للتوسع — يمكن إضافة عملات أخرى بسهولة (لو احتيج).

### نقاط متوسطة 🟡
1. الإملاء غير المُدقَّق للأعداد الكبيرة جداً (كوادرليون/كوينتليون).
2. كلمة الوصل بمسافة قبلها تنتج فراغات مزدوجة في بعض النواتج.
3. عدم التمييز الكامل بين الجنس النحوي للوحدة والكسر (sGender في القاموس = male).
4. التطبيق يعتمد كلياً على JavaScript — لو فشل، لا تفقيط في الإيصال.
5. التمويه (`_$_174b`) يصعّب الصيانة دون مبرر تقني واضح.

### نقاط حرجة 🔴
1. **"اثنين" مرفوع خطأ** — يجب أن تكون "اثنان" عند الرفع.
2. **uSingle = uDouble = uPlural = "ريال يمني"** — يلغي قاعدة الجمع العربية تماماً.
3. **negatives تُجرَّد بصمت** — مبلغ -100 ينتج "مائة ريال" (إخفاء عيب).
4. **`tafqeet("123abc")` يقبل ويُنتج خرجاً مشوهاً** — لا validation.
5. **`tafqeet(0.005)` يُهمل الفلس** — قد يخسر المال (في حالات نظرية بحتة لأن الـ Java يرسل String بدون فاصلة على أي حال).
6. **لا يوجد تفقيط احتياطي في Java** — أي عطل في WebView يعني إيصال بدون كلمات.
